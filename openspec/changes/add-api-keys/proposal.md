# Proposal

## Why

کاربر باید بتواند برای نرم‌افزارهای دیگر سازمان، کلید API مدل یا عاملی را که به آن دسترسی دارد بگیرد، به شرط اینکه ادمین به گروهش اجازه داده باشد. نیازمندی: «ارائه‌ی API برای دسترسی به مدل‌ها، پایگاه دانش و عامل‌ها و تبادل اطلاعات با سایر نرم‌افزارها».

## What Changes

- آیتم **API من** در منوی کناری و صفحه‌ی `/api-keys`.
- فهرست کلیدهای خود کاربر (نام، نوع و منبع، چند حرف آخر، تاریخ ساخت و انقضا، آخرین استفاده، وضعیت) و ابطال هر کلید با تأیید.
- **کلید تازه**: نام، نوع (فقط نوع‌های مجاز گروه‌های کاربر)، مدل یا عامل از میان چیزهایی که کاربر خودش دسترسی دارد (یا «پایگاه دانش سازمان»)، و انقضا (بدون انقضا، ۳۰ روز، ۹۰ روز، یک سال). سقف مصرف ماهانه‌ی تعیین‌شده‌ی ادمین زیر فرم نوشته می‌شود.
- متن کلید بعد از ساخت **فقط یک بار** با دکمه‌ی کپی نشان داده می‌شود.
- اگر هیچ‌کدام از گروه‌های کاربر اجازه نداشته باشد، صفحه می‌گوید برای دسترسی با ادمین تماس بگیرید.
- راهنمای استفاده با نمونه‌ی `curl` برای هر نوع مجاز.

## Impact

مسیرهای `GET/POST /api/api-keys` و `POST /api/api-keys/[id]/revoke`، فایل مشترک `src/lib/api-keys.ts` و `provider-store.ts` (یکسان با پنل ادمین)، بخش `api-keys` در `user-shell`، و `searchable-select` که حالا بالای پنجره‌ها باز می‌شود (`z-modal`).

## Out of Scope

خود درگاه‌های `/api/v1/...` (نمونه‌ی `curl` ساختار برنامه‌ریزی‌شده را نشان می‌دهد)، شمارش واقعی مصرف و «آخرین استفاده»، اعمال سقف ماهانه، تعیین نوع کلید پایگاه دانش به‌تفکیک سند، وب‌هوک، احراز هویت واقعی.
