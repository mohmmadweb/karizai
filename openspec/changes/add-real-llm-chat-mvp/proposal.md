# Proposal

## Why

کاربر یک کلید API از یک مدل زبانی دارد و می‌خواهد آن را در پنل ادمین ثبت کند و در پنل کاربر با آن واقعاً چت کند. این یعنی آغاز یک بک‌اند ساده‌ی MVP داخل Next.js (فاز ۲، فقط برای همین بخش)؛ بعداً به سرویس بک‌اند خود کاربر وصل می‌شود.

## What Changes

- **پنل ادمین**: ثبت ارائه‌دهنده (نام، نشانی، کلید) واقعاً ذخیره می‌شود؛ کلید فقط روی سرور و رمزنگاری‌شده می‌ماند و هرگز برنمی‌گردد. فهرست مدل‌ها واقعاً از ارائه‌دهنده گرفته می‌شود. فعال‌کردن مدل و ویژگی‌هایش ذخیره می‌شود و بعد از تازه‌کردن صفحه می‌ماند.
- **پنل کاربر**: فهرست مدل‌ها همان مدل‌های فعال‌شده توسط ادمین است. چت با آن‌ها واقعاً پاسخ جریانی از مدل می‌گیرد، با امکان توقف و تلاش دوباره. اگر ادمین هنوز مدلی فعال نکرده، فهرست نمونه می‌ماند.
- ارائه‌دهنده باید با API سازگار با OpenAI کار کند (`/models` و `/chat/completions`).

## Capabilities

### New Capabilities
- `admin-provider-backend`، `user-real-chat`.

### Modified Capabilities
هیچ.

## Impact

دو پنل یک پوشه‌ی داده‌ی مشترک می‌خوانند (`moshekaf-data`) و هر کدام یک `.env.local` با راز رمزنگاری دارند. مسیرهای `/api/*` در هر دو پنل. قفل فاز ۱ فقط برای همین بخش‌ها برداشته شد؛ بقیه‌ی بخش‌ها (دسترسی، سهمیه، ابزار، Agent، OCR، وب‌سرچ) همچنان نمونه‌اند.

## Out of Scope

ورود و دسترسی واقعی کاربران، سهمیه‌ی واقعی، ابزار و Agent واقعی، دستیار سند و داده، پیوست فایل برای مدل، مدل‌های غیرسازگار با OpenAI، تغییر دسترسی گروه‌ها به مدل.
