# Design

- Feature `src/features/workflows`: `types`, `data` (templates, workflows, runs), `lib` (`graph` for cycle/start/upstream/run order, `validate-workflow`, `describe-trigger`, `generate-from-text`), `hooks` (`use-workflow-draft`, `use-run-engine`), `components`.
- State: one `WorkflowsProvider` in the `(app)` layout holds workflows and runs in memory. `useRunEngine` simulates runs with timers; an approval step waits on a promise resolved by `decide()`. A step whose instruction contains «خطا» fails (test aid). Nothing runs on a server.
- Canvas: `@xyflow/react` (React Flow 12) in `EditorCanvas`, vertical flow (handles top and bottom, so direction does not depend on RTL). The wrapper has `dir="ltr"`, nodes set `dir="rtl"`. In controlled mode the measured sizes from `dimensions` changes must be passed back as `measured`, or nodes stay hidden. Only runs started in this session (`run-new-*`) light up steps.
- Edit flow: `useWorkflowDraft` keeps a draft until Save; `useUnsavedGuard` (shared with the Agent form) warns on leaving.
- Governance rules in the UI: schedule/event triggers → `pending-approval` on activate (`needsApproval`); `validateWorkflow` blocks unattended tools that need approval unless an approval step is upstream; orchestrator needs child Agents and a step cap.
- Routes: `/workflows` (list, loading), `/workflows/[workflowId]` (Suspense; `?tab=runs`). Sidebar item «کارهای من».
- Block picker: `BlockPicker` (the «+» at the output of each `FlowStepNode`) is a drop-down with sub-menus built from `useAgents` and `useConnections`; `useWorkflowDraft.addAfter` creates the filled-in node and its edge. New step kind `skill` (`NodeConfig.skillId`) with validation that the skill is approved.
- Update: the add-step toolbar (`NodePalette`) was removed. The output `Handle` of each step is the «+» (trigger of `BlockMenu`, `nativeButton={false}`); visible on hover or focus, always when the step has no output edge (`data.hasOutput`). The menu opens on click only (it ignores `trigger-press`) so dragging from the handle still connects. An empty canvas shows the dashed «افزودن گام اول…» box that opens the same menu and calls `addFirst`.
- Token cost: `RunStep` gains `modelName`, `inputTokens`, `outputTokens`. `useRunEngine` assigns typical amounts per step kind (`tokensOf`; tools and approvals spend none) and the Agent's default model name (`modelNameOf` from `WorkflowsProvider`). `lib/run-cost.ts` (`tokensOfRun`, `costByStep`, `totalTokens`) feeds `CostSummary` (Runs tab), the run list, and the run detail. Amounts are estimates for the simulation; a money amount needs model prices from the admin panel and is not shown yet. Workflow runs do not yet subtract from the chat quota.
